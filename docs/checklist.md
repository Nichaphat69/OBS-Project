## 5. ⚠️ ปัญหาที่ใหญ่ที่สุดตอนนี้ — ประตูมนุษย์อยู่ผิดขั้น

n8n workflow ทั้งสองไฟล์**ยิงสร้างร่างเองโดยไม่มีคนมาเกี่ยวเลย**

```
01-ingest:  Gmail → IF อนุมัติ → ingest → switch → สร้างร่างใน FlowAccount     ← ไม่มีคน
02-daily:   ทุกวัน 09:00 → /cycles/ready → IF → สร้างร่างใน FlowAccount        ← ไม่มีคน
```

และปุ่ม "อนุมัติและสร้างร่างใน FlowAccount" บนหน้าเว็บ ก็เรียก endpoint เดียวกันนี้

### ทำไมถึงไม่ผิดเท่าที่เห็น
เอกสารข้อ 3.5 บอกว่า "สร้างเป็น Draft" เป็นงาน**อัตโนมัติ** ประตูมนุษย์ของเอกสารอยู่ที่ **4.2 กั้น 4.3 (เปลี่ยนสถานะใน FlowAccount) และ 4.5 (ส่งเมล)**

### แต่ปัญหาจริงคือ
**ข้อ 4.2 · 4.3 · 4.5 ยังไม่ได้ทำเลยแม้แต่ข้อเดียว** ระบบจึงหยุดอยู่ที่ "มีร่างใน FlowAccount + ร่างเมลในฐานข้อมูล" แล้วไม่มีใครสั่งต่อได้

### สิ่งที่ยังกันไว้ได้
`/approve` คืน **409** ถ้ายังมี blocker ค้าง → n8n สร้างร่างไม่ได้ถ้าตรวจ Manday ไม่ผ่าน

### ต้องแก้
1. เปลี่ยนชื่อ endpoint/ปุ่มให้ตรงความจริง — มันคือ "สร้างร่าง" ไม่ใช่ "อนุมัติ"
2. สร้างประตูมนุษย์จริงที่ 4.2 → กั้น 4.3 + 4.5

## 6. ส่วนที่ทำเกินเอกสาร — รอตัดสินใจ

เอกสารระบุ stack ว่า **"n8n + LLM"** · Human Approval เกิดที่ LINE/Email + n8n Wait for Webhook · Master Data อยู่ใน **"DB/Google Sheet"** — **ไม่ได้ระบุหน้าเว็บเลย**

| ส่วน | เหตุผลที่ควรลบ | สถานะ |
|---|---|---|
| **หน้าแดชบอร์ด** (6 การ์ด + กราฟ) | หน้ารายงาน ไม่ใช่ขั้นตอนทำงาน | รอตัดสิน |
| **หน้าใบแจ้งหนี้** | ทะเบียนซ้ำกับ FlowAccount ที่เป็นเจ้าของข้อมูล | รอตัดสิน |
| **หน้าพนักงาน · ลูกค้า&สัญญา** | อ่านได้อย่างเดียว แก้ไม่ได้ → ไม่ได้ลดงาน manual | รอตัดสิน |
| **หน้าตั้งค่า** | อ่านได้อย่างเดียวเหมือนกัน | รอตัดสิน |
| **กระดิ่งแจ้งเตือน** | ข้อ 2.6 ให้แจ้ง LINE · กระดิ่งบังคับให้คนมานั่งเปิดเว็บ = ยิ่ง manual | รอตัดสิน |
