สรุประบบ

ระบบนี้คืออะไร

เครื่องมือภายในของฝ่ายบัญชี iPassion สำหรับวางบิลค่าบริการพนักงาน Outsource ที่ไปประจำอยู่ที่ออฟฟิศลูกค้า ระบบรับช่วงงานตั้งแต่ได้ใบบันทึกเวลา (Timesheet) ที่ลูกค้าอนุมัติแล้ว ไปจนถึงร่างใบแจ้งหนี้ในระบบบัญชีและร่างอีเมลวางบิล

หลักการที่คุมทั้งระบบ — ระบบเตรียมเอกสารให้เสร็จ แต่ไม่ตัดสินใจแทนคน ทุกใบยังต้องมีคนตรวจและกดเอง และระบบไม่ส่งอีเมลออกหาลูกค้าเองเด็ดขาด

ใช้ทำอะไร

งานที่แทนคนได้เดิมทำยังไง
อ่าน Timesheet คนเปิดไฟล์ PDF อ่านตาราง 28–31 แถวเอง แล้วพิมพ์ตัวเลขลง Excel
ตรวจ Manday คนไล่นับวันทำงาน หักเสาร์–อาทิตย์และวันหยุดเอง แล้วเทียบกับที่พนักงานกรอกมา
คิดเงินและออกใบแจ้งหนี้ คนคูณเรท หักส่วนลดวันลา คิด VAT และภาษีหัก ณ ที่จ่าย แล้วคีย์เข้า FlowAccount ทีละช่อง
ร่างอีเมลวางบิล คนพิมพ์อีเมลใหม่ทุกเดือน พร้อมไล่ตัวเลขจากใบแจ้งหนี้มาใส่

ใครใช้บ้าง และใช้ส่วนไหน

ผู้จัดการโครงการฝั่งลูกค้า
ไม่ได้ใช้ระบบ		 — ตรวจและอนุมัติ Timesheet แล้วส่งอีเมลแจ้งอนุมัติกลับมาให้ iPassion
ผู้ดูแลระบบ / ทีมพัฒนา หน้าข้อมูลหลัก และไฟล์ตั้งค่า .env ตั้งค่า API key · ต่อ Gmail · เพิ่มพนักงานและเรทค่าบริการ · ปรับปฏิทินวันหยุด · เพิ่มชื่อพ้อง
n8n โหมด Auto เรียกผ่าน API ไม่เข้าหน้าเว็บ ตัวจุดชนวนและตั้งเวลา — ดึงอีเมลเข้าระบบ และถามทุกเช้าว่ารอบไหนพร้อมวางบิล
ข้อจำกัดเรื่องผู้ใช้ที่ต้องรู้ — ตอนนี้ระบบมี สิทธิ์เดียว ไม่มีระบบล็อกอิน ใครเปิดหน้าเว็บได้ก็ทำได้ทุกอย่าง ชื่อผู้กดมาจากค่า ACTOR ในไฟล์ตั้งค่า ถ้าจะใช้กันหลายคนจริง ต้องต่อกับ SSO ของบริษัทก่อน

1. การทำงานของระบบปัจจุบัน

ทำงานเป็น 4 ขั้นเรียงกัน แต่ละขั้นแยกชัดว่าคนต้องกดอะไร และระบบทำอะไรให้ ข้ามขั้นไม่ได้

1
รับ Timesheet เข้าระบบ
คน เลือกทางเข้า 3 ทาง — ดึงจาก Gmail · ลากไฟล์ PDF มาวาง · กรอกเอง แล้วตรวจสิ่งที่ AI อ่านมา แก้ได้ทุกช่อง จากนั้นกดยืนยันบันทึก
ระบบ Claude อ่านไฟล์ PDF และเนื้ออีเมล → จับคู่ชื่อพนักงานกับฐานข้อมูล → คำนวณ Manday · ยังไม่บันทึกจนกว่าคนจะกดยืนยัน
2
ตรวจ Manday
คน เปิดดูปฏิทินรายเดือนและผลตรวจ แล้วเลือก — กดยืนยันว่าตรวจแล้ว · ตีกลับให้แก้ · หรือแก้ที่ต้นเหตุ (ชื่อพ้อง เรท วันหยุด) แล้วสั่งคำนวณใหม่
ระบบ ตรวจ 8 เงื่อนไขเทียบกับปฏิทิน เช่น วันทำงานรวมกับวันลาตรงกับเดือนนั้นไหม ลาตรงวันหยุดหรือเสาร์–อาทิตย์หรือเปล่า · ไม่ผ่าน = ไปขั้น 3 ไม่ได้
3
วางบิลใน FlowAccount
คน เปิดรอบบิล ดูใบแจ้งหนี้จำลองคู่กับข้อมูลที่จะยิงเข้า API แล้วกดอนุมัติและสร้างร่าง
ระบบ รอ Timesheet ครบทุกคนในรอบก่อน → ประกอบใบแจ้งหนี้ใบเดียวรวมทุกคน → สร้างเอกสารใน FlowAccount เป็นร่างเท่านั้น
4
ร่างอีเมลถึงลูกค้า
คน คัดลอกร่าง หรือเปิดกล่องเมล หรือให้ระบบวางร่างไว้ใน Gmail → แนบเอกสารและกดส่งเอง → กลับมากดบันทึกว่าส่งแล้วเพื่อปิดงาน
ระบบ Claude เรียบเรียงอีเมลจากตัวเลขที่คำนวณไว้ พร้อมอธิบายว่าเดือนนี้ ต่างจากเดือนก่อนเพราะอะไร · ระบบไม่ส่งเมลเอง

สองประตูที่ข้ามไม่ได้

ประตูถ้าไม่ผ่านจะเกิดอะไร
ตรวจ Manday ไม่ผ่าน ปุ่มอนุมัติถูกปิด และ API ตอบกลับพร้อมบอกว่าติดที่ใครและติดเรื่องอะไร
ยังไม่มีคนกดยืนยัน รอบบิลค้างที่สถานะ “รอคนตรวจ” · ตัวตั้งเวลาของ n8n จะไม่เห็นรอบนี้เลย
ตราที่ประทับว่า “คนตรวจแล้ว” ผูกกับยอดชุดที่คนเห็นตอนกด ถ้ายอดเปลี่ยนทีหลัง เช่น ลูกค้าส่ง Timesheet ฉบับแก้มาทับ หรือมีคนเพิ่มวันหยุด ตราจะหมดอายุเอง และรอบบิลกลับไปติดที่ขั้น 2 อีกครั้ง

3. เปรียบเทียบการทำงาน Manual กับ Auto

กฎการคิดเงินและการตรวจเป็นชุดเดียวกันทั้งสองโหมด ต่างกันแค่ใครเป็นคนกดปุ่ม สลับโหมดด้วยค่าตั้งค่าตัวเดียวคือ requireHumanCheck

ขั้น Manual (ใช้อยู่ตอนนี้) Auto (เป้าหมาย) ใครเป็นคนทำ
1 · รับ Timesheet คนเลือกอีเมลในระบบ หรือโหลดไฟล์มาอัปโหลดเอง พร้อมกรอกเลขที่เอกสาร Gmail trigger จับหัวข้อ “แจ้งอนุมัติเอกสาร TimeSheet” ทุก 30 นาที แล้วดึงไฟล์แนบเอง Manual: คน
Auto: n8n
1.1 · อ่านไฟล์ Claude อ่าน PDF ตัวเดียวกัน โมเดลเดียวกัน ทั้งสองโหมด ระบบ (LLM)
1.2 · ตรวจสิ่งที่ AI อ่าน แสดงบนจอให้คนดูก่อน แก้ได้ทุกช่อง กดยืนยันจึงบันทึก ไม่มีขั้นนี้ — อ่านแล้วบันทึกทันที Manual: คน
Auto: ข้าม
2 · ตรวจ Manday เครื่องตรวจ 8 เงื่อนไขเทียบปฏิทินให้อัตโนมัติ เหมือนกันทั้งสองโหมด ระบบ
2.1 · ยืนยันผลตรวจ คนเปิดดูปฏิทินแล้วกดยืนยัน ไม่กดคืออนุมัติวางบิลไม่ได้ ไม่มีขั้นนี้ — ตรวจผ่านแล้วไหลไปขั้น 3 เอง Manual: คน
Auto: ข้าม
2.2 · เจอปัญหา คนเลือกเอง — ตีกลับ เพิ่มชื่อพ้อง แก้เรท หรือเพิ่มวันหยุด แล้วคำนวณใหม่ แจ้ง LINE ทีมแอดมิน แล้วรอคนเข้ามาทำเหมือนโหมด Manual คน ทั้งสองโหมด
3 · วางบิล คนเปิดรอบบิล ดูใบจำลอง แล้วกดอนุมัติสร้างร่าง n8n ถามระบบทุกวันทำการ 09:00 ว่ารอบไหนพร้อม แล้วสั่งสร้างเอง Manual: คน
Auto: n8n
3.1 · สร้างเอกสาร ยิงเข้า FlowAccount ได้เป็นร่างเท่านั้น เหมือนกันทั้งสองโหมด ระบบ
4 · ร่างอีเมล Claude เรียบเรียงจากตัวเลขที่ระบบคำนวณไว้ ห้ามคิดเลขเอง ระบบ (LLM)
4.1 · ส่งอีเมล ระบบไม่ส่งเองทั้งสองโหมด — คนแนบเอกสารและกดส่งเสมอ คน ทั้งสองโหมด

4. อีเมลถูกยิงตรงไหนบ้าง

อีเมลในระบบมี 3 จุด แยกตามทิศทาง ทั้งโหมด Manual และ Auto

จุด ทิศทาง โหมด Manual โหมด Auto
ขาเข้า — ลูกค้าแจ้งอนุมัติ Timesheet ลูกค้า → เรา ต่อ Gmail แล้ว กด “ดึงรายการเมล” แล้วเลือกฉบับที่จะเอาเข้าระบบเอง · ยังไม่ต่อ Gmail ก็โหลดไฟล์แนบมาอัปโหลดเอง Gmail trigger ดึงเองทุก 30 นาที ตามหัวข้อที่กำหนด แล้วเช็คว่าสถานะเป็น “อนุมัติ” จริง
แจ้งเตือนทีมเมื่อตรวจไม่ผ่าน ระบบ → ทีมเรา ไม่มีการยิงอีเมล — คนเห็นจากป้ายตัวเลขบนเมนูขั้นที่ 2 และการ์ดงานที่ต้องทำบนแดชบอร์ด แจ้งผ่าน LINE Business ตามที่เอกสารออกแบบระบุ ยังไม่ได้ทำ
ขาออก — วางบิลถึงลูกค้า เรา → ลูกค้า เลือกได้ 3 ทาง — คัดลอกร่าง · เปิดโปรแกรมอีเมลพร้อมเนื้อความ · ให้ระบบวางร่างไว้ในกล่อง Drafts ของ Gmail แล้วคนกดส่งเอง สร้างร่างใน Gmail ให้เลยหลังสร้างเอกสารเสร็จ แต่ยังไม่กดส่งเหมือนกัน
หลักที่ไม่เปลี่ยนทั้งสองโหมด — ระบบไม่ส่งอีเมลออกหาลูกค้าเอง และไม่กดอนุมัติเอกสารในระบบบัญชีเอง หลักประกันข้อนี้อยู่ที่ตัวโค้ด ไม่ใช่ที่การตั้งค่า คือในไฟล์ตัวเชื่อม Gmail ไม่มีคำสั่งส่งอีเมลอยู่เลย และในไฟล์ตัวเชื่อม FlowAccount ก็ไม่มีคำสั่งอนุมัติเอกสารเช่นกัน

สิทธิ์ใช้ทำอะไร

สร้างและแก้ร่าง วางร่างอีเมลวางบิลไว้ในกล่อง Drafts (ขั้นที่ 4)

หมายเหตุตรงไปตรงมา — Google ไม่มีสิทธิ์แบบ “สร้างร่างได้แต่ส่งไม่ได้” สิทธิ์สร้างร่างจึงแถมสิทธิ์ส่งมาด้วยโดยเลี่ยงไม่ได้ หลักประกันว่าระบบจะไม่ส่งจึงอยู่ที่โค้ดที่ไม่มีคำสั่งส่ง ไม่ใช่ที่ตัวสิทธิ์

5. หน้าจอในระบบ

มี 6 หน้า เรียงตามลำดับงานที่คนต้องเดิน หน้าแรกที่เปิดขึ้นมาคือแดชบอร์ด

หน้าอยู่ขั้นไหนทำอะไรได้ที่นี่
แดชบอร์ด ไว้ดู ภาพรวมว่าเงินค้างอยู่ขั้นไหน — จำนวนใบที่รอคนตรวจ ใบที่ยืนยันแล้วรอวางบิล และยอดที่วางบิลไปแล้ว · กราฟมูลค่ารายเดือนเทียบกับเรทตามสัญญา · สัดส่วนสถานะรอบบิล · การ์ดงานที่ต้องทำที่กดเข้าไปทำต่อได้ทันที · ความคืบหน้าสัญญา · เหตุการณ์ล่าสุดในระบบ
1 · อัปโหลด Timesheet ขั้น 1 เลือกทางเข้า 3 แท็บ — ดึงจาก Gmail · ลากไฟล์ PDF มาวาง · กรอกเอง จากนั้นระบบแสดงสิ่งที่ AI อ่านได้ให้ตรวจ แก้ได้ทุกช่อง พร้อมบอกว่าจับคู่กับพนักงานคนไหนและสัญญาไหน แล้วจึงกดยืนยันบันทึก
2 · ตรวจ Manday ขั้น 2 กล่องงานแสดง Timesheet เป็นการ์ด พร้อมตารางคำนวณย่อในตัว มีตัวกรอง 5 หมวด เรียงลำดับ 5 แบบ และช่องค้นหา
— หน้าตรวจ Timesheet ขั้น 2 หน้าย่อยของกล่องงาน แบ่ง 4 แท็บ — ภาพรวมการคำนวณและผลจับคู่ชื่อ · ที่มาของไฟล์และข้อมูลดิบที่ AI อ่าน · ปฏิทินรายเดือนแบบภาพแยกสีวันทำงาน วันลา วันหยุด และเสาร์–อาทิตย์ · ผลตรวจทุกข้อพร้อมเหตุผล ปุ่มที่นี่คือ ยืนยันว่าตรวจแล้ว · ตีกลับ · คำนวณใหม่
3 · วางบิล & ร่างอีเมล ขั้น 3–4 กางทุกเดือนตามช่วงสัญญา รวมเดือนที่ยังไม่ได้เอกสาร แสดงสถานะรอบบิล 5 แบบ — รอ Timesheet · ได้ไม่ครบ · รอคนตรวจ · รออนุมัติ · วางบิลแล้ว พร้อมมูลค่าและกำหนดเวลาของแต่ละรอบ
— หน้าอนุมัติรอบบิล ขั้น 3–4 หน้าสำคัญที่สุด แบ่งสองคอลัมน์ ซ้ายเป็นการ์ดรายคนพร้อมการคำนวณ และแท็บข้อมูลที่จะยิงเข้า FlowAccount กับร่างอีเมล ขวาเป็นใบแจ้งหนี้เสมือนจริงที่ค้างไว้ตลอดเวลาเลื่อน ปุ่มอนุมัติอยู่แถบล่าง และถูกปิดไว้ถ้ายังมีอะไรค้าง
ใบแจ้งหนี้ ไว้ดู ทะเบียนเอกสารที่ระบบสร้างเข้า FlowAccount กางยอดหลังส่วนลด VAT ภาษีหัก ณ ที่จ่าย และยอดรับชำระของทุกรอบไว้เทียบกันในตารางเดียว พร้อมแถวรวม
ข้อมูลหลัก ตั้งค่า รวม 3 แท็บ — พนักงานและชื่อพ้องที่ยอมรับ (แก้เรทได้) · ลูกค้าและเงื่อนไขสัญญา · ปฏิทินวันหยุดและสถานะการเชื่อมต่อ เข้ามาที่นี่เมื่อขั้นที่ 2 แจ้งว่าจับคู่ชื่อไม่ได้หรือเรทไม่ตรง

สิ่งที่ช่วยให้ไม่ต้องคอยกดรีเฟรช

  • ป้ายตัวเลขแดงบนเมนูขั้นที่ 2 และ 3 บอกจำนวนงานค้างของขั้นนั้น และขยับเองเมื่อมีของใหม่
  • กระดิ่งบนแถบบนบอกว่ามีอะไรเพิ่งเกิดขึ้นในระบบ พร้อมนับรายการที่ยังไม่ได้อ่าน
  • แถบบนบอกสองอย่างตลอดเวลา — โหมดของ FlowAccount และโหมดของระบบ (Manual หรือ Auto)
  • เมนูข้างย่อเหลือแต่ไอคอนได้ เพื่อคืนพื้นที่ให้หน้าที่มีตารางกว้าง

เรื่องผลตอนนี้
ดึงไฟล์ PDF ใบแจ้งหนี้จาก FlowAccount ร่างอีเมลที่สร้างมีแต่ข้อความ ไม่มีไฟล์แนบ คนต้องไปโหลดใบมาแนบเอง
แจ้ง LINE เมื่อตรวจไม่ผ่าน คนต้องเปิดหน้าเว็บมาดูป้ายตัวเลขเอง
ยิง FlowAccount ของจริง ยังเป็นโหมดทดสอบ เลขที่เอกสารเป็นค่าเสมือน และยังไม่เคยรู้ว่าชื่อฟิลด์ถูกต้องจริงหรือไม่
กรณีพิเศษของสัญญา สัญญาเริ่มหรือจบกลางเดือน · ทำงานล่วงเวลา · ลาครึ่งวัน · Timesheet ที่แก้ไขหลังอนุมัติ — ยังไม่มีกฎรองรับ

ต้องการทำไม
อัตราต่อวันหารด้วยอะไร เดือน ม.ค. มีวันทำงาน 20 วันพอดี ทำให้ “หาร 20 คงที่” กับ “หารด้วยวันทำงานจริง” ให้ผลเท่ากัน ยังแยกไม่ออกจากตัวอย่างเดียว — ขอใบแจ้งหนี้อีกเดือนมาเทียบ
ประเภทวันลาที่หักเงิน ตอนนี้หักทุกประเภทเท่ากัน ยังไม่ยืนยันว่าลาป่วย ลากิจ ลาพักร้อน หักเหมือนกันหรือไม่
ปฏิทินวันหยุดของลูกค้า กระทบจำนวนวันทำงานมาตรฐานโดยตรง จึงกระทบอัตราต่อวันและยอดเงิน
ชนิดเอกสารและผังบัญชี ออกเป็น Billing Note หรือ Tax Invoice และใช้ผังบัญชีรายได้ตัวไหน
อีเมลผู้ประสานงานฝั่งลูกค้า ไม่มีแล้วสร้างร่างอีเมลถึงลูกค้าไม่ได้
